## Estructura y flujo real

`n8n/workflows/` y los receptores IMAP gestionados por `n8n/` normalizan mensajes y llaman a `POST /api/automation/emails` y `POST /api/automation/emails/{id}/analyze` (`backend/app/api/automation.py`); también existe ingestión humana autenticada. `backend/app/schemas/email.py` valida el correo normalizado; `backend/app/services/mime_parser.py` es parser interno, no endpoint MIME. `backend/app/services/email_ingestion.py` persiste Email con deduplicación por buzón y Message-ID. `backend/app/services/email_analysis.py` carga contexto activo desde PostgreSQL, llama a reglas y luego al analizador semántico; combina scores, guarda EmailAnalysis y auditoría en una transacción y crea BECAlert cuando procede. `backend/app/services/alerts.py` separa creación de alerta y veredicto humano (claim/release/resolve); `frontend/src/pages/` contiene dashboard, correos, alertas y revisión. El informe académico existente reside en `backend/app/evaluation/`; no está conectado a rutas HTTP. n8n puede conservar contenido en historial, por lo que el experimento no debe usar cuentas operativas.

Actualmente existen utilidades `eval-v2` y un grid de 25 políticas, pero no hay resultados nuevos ejecutados aquí. El README contiene pasajes anteriores a FALLBACK que dicen ERROR/502 ante fallos LLM; el código vigente usa FALLBACK para fallos semánticos y reserva ERROR para fallos sin score evaluable. ## Decisión y riesgos

Clasificación: **evaluable ahora con fixtures para regresión técnica**: reglas, combinador, fallback y métricas; **configurable fuera de producción**: pesos, umbrales y pisos; **entrenable condicionalmente**: nuevo clasificador supervisado con corpus independiente y permiso de uso; **fuera del alcance sin autorización**: llamadas LLM externas, despliegue, correo real y cambios de política operativa. Una validación cruzada del conjunto histórico, sin grupos y con development usado para diseñar reglas, no puede demostrar generalización. Tampoco se debe reetiquetar el holdout de 42 como test nuevo.

Evidencia local: `uv run --no-sync python -m app.scripts.validate_dataset` confirmó 140/100/40 y 30 negativos difíciles; `--descriptive` observó 98 development, `thread_id` ausente 98/98, cuerpo/asunto presentes 98/98, `authentication_results` ausente 87/98. `uv run --no-sync pytest -q` informó **333 aprobadas, 277 omitidas, 1 warning de dependencia**; `uv run --no-sync ruff check app/evaluation app/services/dataset.py` aprobado. `tests/test_dataset.py`, `test_evaluation.py`, `test_hybrid_scoring.py`, `test_deterministic_analysis.py` y `test_policy_experiment.py` tienen verificaciones con fakes. Sin `TEST_DATABASE_URL` no se probaron integraciones PostgreSQL; no se utilizó `.env`, cuentas IMAP ni proveedor externo. Criterio de avance de fase 0 cumplido: mapa y decisión de no entrenamiento documentados; fase 1 debe fijar protocolo y necesidades de recolección antes de programar modelos.
